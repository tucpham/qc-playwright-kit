# 03 - AI workflow: plan -> generate -> heal -> review

## The role of AI

| Right | Wrong |
|---|---|
| AI explores the app and drafts test cases for humans to approve | AI decides expected results from the app's current behavior |
| AI generates Playwright code; humans review and commit it | On every regression run, AI reads test cases and drives the app itself |
| AI proposes fixes for broken tests as a PR | AI rewrites tests at runtime to make them "pass" |
| AI pre-reviews test PRs against the checklist | AI replaces the human reviewer |

Why: regression needs **the same input, the same expected result, and repeatable outcomes**. An LLM running directly is not deterministic; it can "adapt itself" when the UI changes and report a pass exactly when it should have caught a bug.

## Tools

- **MCP server**: `.mcp.json` declares `playwright-test` (`npx playwright run-test-mcp-server`), providing browser tools + running/debugging tests.
- **Playwright agents** (`.claude/agents/`): planner, generator, healer. Generated by `npm run agents:init`; must be regenerated after upgrading Playwright.
- **Company rules**: `AGENTS.md` (overrides the agents' default instructions when they conflict).
- **Standard prompts**: `ai/prompts/*.md`, usable with any AI tool (paste the content into the chat if you are not using Claude Code).
- **Claude Code commands**: `/qc-plan`, `/qc-generate`, `/qc-heal`, `/qc-review`, `/qc-import`.

Using Copilot / Cursor: these tools read `AGENTS.md`; create the agents with `npx playwright init-agents --loop=vscode` (or `copilot`), then paste the prompt content from `ai/prompts/`.

> Note: `init-agents` overwrites `.mcp.json`. Re-check this file afterwards.

## Workflow

```
specs (draft) ──/qc-plan──> QC/BA approve ──> specs (approved)
                                                  │
                                            /qc-generate
                                                  │
                         tests/*.spec.ts ──> stabilize 5/5 ──> verify ──> /qc-review + human review ──> merge
                                                                                                          │
                                                                                          CI runs deterministically (no AI)
                                                                                                          │
                                                                                           red test ──> /qc-heal ──> fix PR
```

## Heal: 4 kinds of cause

| Kind | Example | What AI may do |
|---|---|---|
| A. UI changed, same behavior | "Save" button renamed to "Save changes" per a new requirement already reflected in the spec; layout changed | Update the locator in the Page Object |
| B. Timing / flaky | Clicking before data has loaded | Replace with web-first assertions, isolate data |
| C. Data / environment | Test account locked, old data deleted | Fix setup/cleanup |
| D. Behavior differs from the spec | Wrong message, wrong total, lost permission | **Do not change the test**. Report a bug; a human decides |

Playwright's default healer is allowed to mark `test.fixme()` when it thinks the app is broken. The kit **forbids** this (AGENTS.md) and `npm run guard` blocks it in CI.

## Tips for using it effectively

- Generate in batches of 3-5 TCs; review before continuing. Nobody reviews 50 tests generated at once carefully.
- Good Page Objects early on make later generations faster and more consistent.
- When AI reports "Testability gaps", collect them and send them to dev every sprint. This is how QC feeds back into code quality.
- Keep `app-map.md` up to date: AI reads it every time; when something is missing, AI guesses.
